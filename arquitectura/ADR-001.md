# ADR-001 · Separar la lógica de tareas de la interfaz

## Contexto

El sistema tiene una lógica encargada de administrar las tareas y otra encargada de mostrar la información en pantalla. Si ambas dependieran directamente entre sí, un problema o cambio en la interfaz podría afectar la gestión de las tareas.

## Driver que manda

Un error al gestionar una tarea no debe afectar las demás tareas del sistema.

## Decisión

`tasks.js` **NO puede importar `ui.js`**.

El módulo `tasks.js` debe encargarse únicamente de administrar las tareas en memoria y no debe conocer cómo se muestran en pantalla. `app.js` será el encargado de coordinar `tasks.js` con `ui.js`.

Así, la lógica de las tareas permanece independiente de la interfaz.

## Alternativa descartada

Hacer que `tasks.js` importe directamente `ui.js` para actualizar la pantalla cada vez que se cree, modifique o elimine una tarea.

Era lo más obvio porque permitiría actualizar la interfaz inmediatamente desde la lógica de tareas, pero mezclaría responsabilidades y haría que un problema de la interfaz pudiera afectar al módulo encargado de las tareas.

## Qué pagamos

Pagamos con más código de coordinación en `app.js`, porque ahora `app.js` debe llamar a `tasks.js` y después pedirle a `ui.js` que actualice la interfaz.
